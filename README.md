# 游戏配置表校验器

> 【一句话待补】谁在什么场景下用它、它替代了什么做法。
策划改完表打包前可以跑一遍，避免肉眼检查时容易出现的疏漏，便于数值策划规划数值的指定，保证数值的合理
---

## 0. 约定：这张表里「空」怎么表示

- `""`（格子空着）与 `0` 等价，都表示「没有」。
- 这条约定对**所有** ID 列和数值列生效。

**代价**：某一列填 `0` 的时候，工具会报该格为空。这只是目前的一个现状，有待修改。

---

## 1. 为什么做

- **谁**在什么情况下会填错：人类在自己实际填写的时候经常会存在一些肉眼难以发现的错误，比如多了一个 0，格式上完美，但是进到游戏里面会迅速报错
- 填错之后**会怎样**：两种结果 —— 1：程序崩溃，完全无法运行；2：可能侥幸通过，但存在极大经济漏洞，被玩家利用导致游戏失衡。
- **以前**怎么发现，**现在**怎么发现：以前纯用肉眼一行行看，现在可以用该工具一次性对数据进行高效精确的检查。

---

## 2. 它查什么

### 2.1 格式检查 `check_config.py`

| 编号 | 检查什么 | 报错文案 | 为什么需要 |
|---|---|---|---|
| R1 | 分解产物2_ID 是空/0，但产物2数量不是空/0 | `分解产物2_ID为空，但是产物2数量不为空` |可能出现刷空产物的bug，影响游戏平衡 |
| R2 | 某格是空/0，且该列允许为空 | 放过（产物2_ID 永远允许空；产物2数量在产物2_ID 也空时允许空） | 允许空的是因为可以只有一个产物 |
| R3 | 某格是空/0，且该列不允许为空 | `XXX为空` | 维护数值稳定，排查错误数据 |
| R4 | 格子不是整数 | `XXX不是数字` | 避免了错误的计算 |
| R5 | 格子是负数 | `XXX为负数` | 避免物品价值受到影响 |
| R6 | ID 列的值不在物品表里 | `引用了不存在的物品ID:XXX` | 避免跨表引用、错误引用 |

分界线：**一格的错在列循环报，两格之间的错在行循环报**（R1 是唯一看两个格子的）。

### 2.2 数值检查 `economy_check.py`

```
投入成本 = 物品价值 + 手续费
期望产出 = 产物1数量 * 产物1价值 + 产物2数量 * 产物2价值
收益比   = 期望产出 / 投入成本
```

判定：收益比大于 1 标「可套利」，否则标「正常」。

【待补】哪些情况不给结论、只标「数据异常」？把触发条件列全。
手续费为负，产物数量为负，不是整数，价值表里查不到这个id

## 3. 怎么用

```bash
# 只查格式
python check_config.py sheet2.csv

# 只查数值
python economy_check.py sheet2.csv

# 两个一起，一个退出码
python check_all.py sheet2.csv
```

真实输出：

```
=====格式检查=====
[]
发现0个错误

=====数值检查=====
物品ID    投入成本    期望产出    收益比     判定
50001   1010    6000    5.94    可套利
50002   1010    5000    4.95    可套利
50003   1010    5000    4.95    可套利
exit = 1

总结果：不通过
```

退出码含义（三个脚本必须一致）：

| 退出码 | 含义 |
|---|---|
| 0 | 全部通过 |
| 1 | 跑完了，但检查不通过 |
| 2 | 没能开始工作（文件找不到 / 空文件 / 用法错） |

## 4. 它拦住了哪些真实的错

| # | 现象（什么输入触发了它） | 后果 | 现在的处理 |
|---|---|---|---|
| 1 | 配置表导出失败，生成一个 0 字节文件 |空表被推送到真实的使用中，一用就崩|os.path.getsize()先获取文件字节数判断是否为0后再往下进行检查 |
| 2 | 表头写出来了，但一行数据都没导出来 | 0行的数据报0个错误，数据会被错误打包上线|判断只有表头时，直接退出 |
| 3 | 某格填了 `abc` | int转换的时候会直接报ValueError|用try/except / ValueError提前捕获并提示数据不是数字 |
| 4 | 3 行都可套利，但 `sys.exit(1)` 写在了行循环里 |第一行直接退出，后面的数据一个都没检查到| 把sys.exit(1)放在行循环外面|
| 5 | 第 1 行可套利、后两行正常 |有套利却报通过，错误的情况被静默吞掉 |检查时遇到可套利等异常先存起来，检查结束之后再统一进行退出，提高改错效率 |
| 6 | 分解手续费填 `-1` |实际投入虚低收益比虚高，存在正常数据却报可套利的可能 |计算前判断是否为负，并直接raise ValueError进入大的try,except中，打印数据异常 |
| 7 | 一张每一行都是乱码的表 | 没有任何正确结论产生，对数值的调整不起作用|except 抓住ValueError→ 标「数据异常」→ 计入结论 → 退出码 1|
| 8 | 产物2_ID 填 `0`（合法的单产物配方） |工具识别到0自动报该数据为空，报错与真实不符 | 通过提前分清为0的每种情况，通过if else进行判断|

## 5. 测试数据怎么跑

| 文件 | 装什么 | 期望 |
|---|---|---|
| `valid_case.csv` | 所有合法形态 | 0 条错误，退出码 0 |
| `bad_case.csv` | 一行一个错 | 6 条错误，退出码 1 |
| `sheet2.csv` | 真实业务样本 | 格式 0 条；数值 5.94 / 4.95 / 4.95 |

保证每条规则都有独立暴露的机会，将每种错误的测试隔离出来，便于在代码修改后比对前后的报错
报6条=全对，报5条=漏了一个，报7条=有重复

## 6. 已知限制

- 从别的目录调用 `check_all.py` 时：两段检查内容为空，因为现在还是从相对路径去调用的，其他人使用时很可能相对路径不是跟我本地的一样|脚本路径改为绝对路径
- 数值列填 `0` 时：会报数值为空，与实际情况不符。|加一个判断该列是否为id列，若是填0算空，
- `check_all.py` 只打印了子进程的 stdout，没打印 stderr，意味着：程序会静默吞报错，难以进行维护|在打印子进程的旁边同时打印stderr
