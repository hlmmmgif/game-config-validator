## 2026-11-23 · 空值语义：从「全局约定」改成「按列规则」

一行前提：v0.1 三段结构定了，输入选 B——需求只给一部分字段，空的那几格交给模型补。为了区分「这格没给」和「策划明确填了 0」，把 `""` 与 `0` 等价的旧约定，拆成按列规则（0 只在 `分解产物2_ID` 这一列表示“没有第二产物”）。

| # | 症状（现象，带当时的输出） | 原因 | 下次怎么做 |
|---|---|---|---|
| 1 | 定了「输入选 B」，只改了 ① 的「输出」格。「输入」格还写着“包含 7 个字段”（那是 A 的假设），「失败」格还把“没说产物数量”列为硬性错误 |修改后没有统一文本的口径|改了代码或者文本后要观察一下有没有一些地方因为修改而变为了bug|
| 2 | 语义改完，README §0 的约定和测试期望没跟着改：文档说 0 是合法值，代码仍把 0 当空。同一条数据，两处说法相反 |修改了一处后没有修改其他的相关的地方，可以说是牵一发而动全身|同1|
| 3 | 验收只跑了 `data/sheet2.csv`，它改前改后都是 0 错误——这个文件证明不了任何事（**第 2 次**，见上面「反复出现的失误」那节） |没有进行多数据验证，结论不具有普适性，而且这里的数据是没有错误的，会让我误以为我改的是对的|修改后每个数据集都测试一下|
| 4 | 为兼容「产物2_ID 填 0」加的 `continue`，只判了“是不是这一列”，没判“值是不是 0”。产物2_ID 引用任何不存在的 ID 都被静默放过（`99999` 跑出 0 个错误） |修改时没有明确好边界|综合考虑前后的代码兼容性，要让代码兼容每一个数据，而不是这行数据可以，换一行就不行了|

**做对的一件事（不是检讨，要留着）**

变异测试：把代码故意改坏，看测试会不会红。

- 变异 1：空值判定改回 `in ["", "0"]` → `test_fee_zero` 红
- 变异 2：去掉 `and val == 0` → `test_product2_id_99999` 红

结论：**通过 ≠ 测到**。以后每个模块至少做一次变异，比反复读代码可靠。
