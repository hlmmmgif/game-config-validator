## 3. 为什么这些都不算「真原话」

判断标准（来自 E2，你自己立的）：**不自己编字段**。同理，不自己编需求。

| 你需要的 | 项目里有的 | 差在哪 |
|---|---|---|
| 策划说的一句话 | 你对 7 个字段的说明书 | 说明书是「已知答案反推问题」，套进去必然填满，测不出②段有没有活 |
| 真实 JD 的职责句 | PDF 里的「岗位要求原话（压缩）」 | 压缩过，且是职责不是需求；职责句不含具体字段 |
| 真实配置表的设计意图 | CSDN 文章的字段清单 | 只有字段和取值，没有「为什么这样设计」 |

**「自己写的需求套自己的字段」= 循环论证。** 这正是 A3 要你去网上找一句真话的原因：只有外来的句子，才会暴露你没预料到的缺口（比如策划根本不会说「手续费」）。

## 8. 用 7.2 那句真需求套你的 7 格（套格结果）

这是 A3 要的实验。规则：需求里**说了**的格子算填得进，**没说**的算填不进。填不进的格，就是②段的活。

| 你的 7 格 | 需求原话里有对应吗 | 能填什么 |
|---|---|---|
| 物品ID | 有（「装备」） | 但装备不是一个 ID，是 `品质 + 强化等级` 两个维度，**一个 ID 装不下** |
| 分解产物1_ID | 有 | 精华 |
| 产物1数量 | 有 | 1 / 3 / 9 / 27 / 81（按品质变） |
| 分解产物2_ID | 有 | 精髓 / 结晶 |
| 产物2数量 | 有 | 0 / 1 / 3 / 9 |
| 分解手续费 | **没有**（只有「返还」和「回购双倍」，都不是收费） | 空 |
| 分解耗时 | **没有** | 空 |

**结果：5 格填得进，2 格填不进。**

但真正的问题不在「填不满」，在于下面这些需求里明说了、而你 7 格**根本没地方放**的东西：

| 需求里明说的 | 7 格里有位置吗 | 说明 |
|---|---|---|
| 装备品质（白/绿/蓝/紫/橙） | 无 | 它是「产物1数量」的**决定条件**，不是一个字段能塞的 |
| 强化等级（+0～+15） | 无 | 决定返还率 |
| 返还率（30%/40%/50%） | 无 | 是公式，不是值 |
| 「有5%概率获得幸运精华」 | 无 | 需要「产物3 + 概率」两格，你一个都没有 |
| 二次确认 / 锁定 / 回购 24h / 批量过滤 | 无 | 全是**流程与 UI 需求**，7 格一格都装不下 |

**这与 7.3 的真实表互相印证**：明日方舟的加工站表有两列你也没有——`副产物概率`（概率）和 `心情消耗`（第二种代价，不是手续费）。**你说「过程成本参数=手续费+耗时」，真实表里代价至少有三类：钱、时间、状态消耗。**

## 9. 结论（可直接拿去改文档）

1. **②段有活干，而且活不在「填字段」。** 5/7 格填得进，说明纯字段搬运确实可以由规则完成。真正需要模型的是那 6 个「7 格装不下」的维度——它们要么是**条件**（按品质取值），要么是**概率**（5% 出副产物），要么是**流程**（二次确认、回购）。这些是「一句话 → 结构化」里唯一没法用 if-else 稳定写完的部分。
2. **A1 的三分法该改了。** 「过程成本参数(手续费, 耗时)」在真实系统里至少是「货币成本 + 时间成本 + 状态成本」三类。你的表只有两格，硬塞会丢信息。
3. **「副产物」是这套表的固有缺口。** 你的 R1 规则只管「产物2_ID 空但数量有值」，默认产物 2 是**必得**的。但真实配方（明日方舟加工站）里第二个产物是**概率产出**，需要额外一列 `副产物概率`。这一列缺了，你的校验器在真实表上会把合法的概率配置判成正常，报不出东西。
