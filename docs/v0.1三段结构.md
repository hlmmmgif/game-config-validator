# v0.1 三段结构

> 过关标准①（2027.02 前）：能画出这张结构图，并说清每段的输入、输出、失败时会怎样。
> 用途：12 月写生成段之前先把接口定下来。这张表填完，写代码就只是往格子里填。
> 规则：每一段只回答自己的问题，不替下一段做事。

---

## 为什么要切成三段

三段必须能各自替换、各自测试。

- 换一家模型 → 只动第②段，①②③ 的接口不变
- 换一张配置表 → 只动第①段
- 加一条校验规则 → 只动第③段

切不开的后果：改提示词要动校验代码，改表结构要重写生成逻辑，最后没人敢碰。

## 第①段 · 输入适配

**它回答的问题**：人说的那句话，怎么变成机器能处理的字段。

| 项 | 填写 |
|---|---|
| 输入是什么（人给的是什么东西、什么形式） |人输入的一句话，可能只包含物品ID,分解产物1_ID,产物1数量,分解产物2_ID,产物2数量,分解手续费,分解耗时(秒)这七个要求的表头数据|
| 输出是什么（交给第②段的到底是什么形状：dict？列表？还是一个字符串） |包含以上参数的字典，如果有些没有给出，则这里的字典的键存在，但是值为空，继续往下进行而不报错，空的交给ai进行填补|
| 这一步**不许**做什么 |不能随便增删关键字段，只做信息的提取|
| 失败时会怎样（比如需求里没说产物数量、说了两个不存在的物品） |遇到硬性错误（物品完全不存在或者手续费填了负数）再报错并终止|
| 出了这种失败，谁来兜底、怎么让人知道 |提示修改后再输入|

## 第②段 · 处理编排

**它回答的问题**：字段怎么被交给模型，模型吐回来的东西怎么保证形状对。

| 项 | 填写 |
|---|---|
| 输入是什么 |第一段返回的字典|
| 输出是什么（必须写清楚"是 JSON 字符串，还是已经解析好的 dict"） |只能是json字符串，不能是````json包裹的块|
| 用什么约束它不许编字段（关键词：schema / JSON mode / 重试） |通过api的json mode和prompt共同约束输出|
| 失败时会怎样（模型吐了非 JSON、吐了表里没有的字段、少了一个必填字段） |网络或格式错误时进行最多3次重试，3次后直接报错退出程序；多吐字段提示报错，继续跑下一条；传来的字典允许有空值，模型吐的json不许有空格|
| 重试几次算够？重试还失败怎么办 |重试最多3次，3次以后报错直接退出|

## 第③段 · 校验输出

**它回答的问题**：一份填好的数据，错在哪、要不要拦。

> 这一段你已经写完了，下面是按你的代码反推的，你看看对不对。

| 项 | 填写 |
|---|---|
| 输入是什么 | 一个 CSV 文件路径（已经是填好的表） |
| 输出是什么 | 错误列表，每条含 `行 / 列 / 等级 / 问题`；另有一个退出码 0=全过、1=跑完但不通过、2=没能开始工作 |
| 这一步**不许**做什么 | 不修数据、不猜原因。只报"哪里不对"，不说"为什么策划这么填" |
| 失败时会怎样 | 文件为空 → 抛 `CheckAbort(code=2)`；只有表头 → `code=1`；文件不存在 → `code=2`；某格不是数字 → 标「数据异常」计入结论 |
| 谁来兜底、怎么让人知道 | 函数只负责发现事实并抛 `CheckAbort`，`main` 统一捕获、打印 message、按 `code` 退出 |

   ▼

   │
   ▼

   │
   ▼
配置表 + 报告
```
